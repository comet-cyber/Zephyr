# BRIEF

更新日期：2026-10-24

## 背景

用户刚入门 Zephyr，能看懂设备树、Kconfig 和驱动文件脉络，目前对 API 和内核不熟悉。已有 Titan Mini、Titan 两块 RA8P1 板，对端为鲁班猫 3（实测 Debian 12）。以打通 WireGuard 为项目主线，不先安排一套全栈课程。

## 目标

- Titan 与鲁班猫 3 分别接入两个不同的网络环境，通过互联网建立 WireGuard 通信路径，完成隧道内应用双向收发。
- Titan 优先使用板载 CYW43438 Wi-Fi 独立联网；网线直连保留为本地联调基线。直接互为 peer 或使用 VPS 中心转发，需按公网可达条件及用户目标选择。
- RA8P1 从隧道发送带序号的应用消息，鲁班猫接收并回显，RA8P1 校验返回消息。
- 能结合实际代码解释 API 的参数、返回值、调用上下文、缓冲区和错误路径。
- 能用日志、网络状态与抓包判断故障位于物理链路、IP/UDP、握手或隧道内应用。

## 非目标

不做双核、NPU、全流量 VPN、整网互通、生产密钥管理或密码学算法自研；不逐行通读整个 HAL/网络栈。Wi-Fi 与跨互联网通信已纳入目标；公网入口待选，不据此部署或修改现有 VPS 服务。

## 约束

- 项目固定为 F:\zephyr\apps\wireguard，沿用已有 west 工作区，不另建环境或升级源码。
- 每次约引入 3–5 个与当前增量直接相关的概念，先解释再让用户参与代码与实验。
- 无时间/功耗/吞吐硬指标；先正确连通、可观察、可恢复，再测性能。
- 板级下载必须单独遵守 SAFETY，项目启动本身不授权下载。

## 成功标准

1. Titan 经板载 Wi-Fi 获得地址、网关及到选定公网端点的可达路径；鲁班猫通过另一网络独立联网。本地以太网与普通 UDP 基线复用已有成功结果。
2. 两端位于不同网络时，wg show 出现近期握手，相关 peer 计数增长，隧道 IP 可达；明确记录是直接 peer 还是中心转发。
3. 隧道中至少 100 条带序号消息完成收发和校验，丢失/超时可统计，不声称绝对无丢包；此项不作为进入 WireGuard 的前置门槛。
4. 抓包能区分外层加密 UDP 与隧道内明文 IP；外层不直接呈现应用消息。
5. RA8P1 重启及断线恢复后再次完成握手/回显，记录恢复时间和失败原因。
6. 用户能解释一次发送路径、一次阻塞等待、一次延期工作及共享状态保护。
