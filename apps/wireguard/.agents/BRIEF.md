# BRIEF

更新日期：2026-10-13

## 背景

用户刚入门 Zephyr，能看懂设备树、Kconfig 和驱动文件脉络，目前对 API 和内核不熟悉。已有 Titan Mini、Titan 两块 RA8P1 板，接收端为安装 Ubuntu 的鲁班猫3。以打通 WireGuard 为项目主线，不先安排一套全栈课程。

## 目标

- RA8P1 与鲁班猫先实现普通 IPv4/UDP 双向通信，再建立 WireGuard 隧道。
- RA8P1 从隧道发送带序号的应用消息，Ubuntu 接收并回显，RA8P1 校验返回消息。
- 能结合实际代码解释 API 的参数、返回值、调用上下文、缓冲区和错误路径。
- 能用日志、网络状态与抓包判断故障位于物理链路、IP/UDP、握手或隧道内应用。

## 非目标

首版不做双核、NPU、Wi-Fi、云部署、全流量 VPN、Linux 网关转发、生产密钥管理或密码学算法自研；不逐行通读整个 HAL/网络栈。

## 约束

- 项目固定为 F:\zephyr\apps\wireguard，沿用已有 west 工作区，不另建环境或升级源码。
- 每次约引入 3–5 个与当前增量直接相关的概念，先解释再让用户参与代码与实验。
- 无时间/功耗/吞吐硬指标；先正确连通、可观察、可恢复，再测性能。
- 板级下载必须单独遵守 SAFETY，项目启动本身不授权下载。

## 成功标准

1. 普通网口 link up、物理 IP 可达，UDP 回显成功。
2. Ubuntu wg show 出现近期握手，双端计数增长，隧道 IP 可达。
3. 隧道中至少 100 条带序号消息完成收发和校验，丢失/超时可统计，不声称绝对无丢包。
4. 抓包能区分外层加密 UDP 与隧道内明文 IP；外层不直接呈现应用消息。
5. RA8P1 重启及断线恢复后再次完成握手/回显，记录恢复时间和失败原因。
6. 用户能解释一次发送路径、一次阻塞等待、一次延期工作及共享状态保护。
